# Raspberry №1–3: что подключить, открыть и нажать

Все программы запускаются **на самой Raspberry Pi**, а не на Windows-ноутбуке.
Нужен учебный комплект Raspberry с microSD, установленной ОС, питанием, монитором,
клавиатурой и мышью. От ноутбука пока требуется только перенести папку с файлами.
Arduino, Android Studio и домашний проект HA для этих трёх работ не используются.

## 1. Скачать репозиторий и открыть Thonny

На Raspberry открыть **Terminal** и выполнить:

```sh
git clone https://github.com/uacw/nis_IoT.git ~/nis_IoT
```

Если `git` не найден: `sudo apt install git`, затем повторить clone.
Если репозиторий уже скачан, вместо clone выполнить:

```sh
git -C ~/nis_IoT pull --ff-only
```

Дальше:

1. Открыть меню Raspberry → **Programming → Thonny**.
2. В Thonny: **File → Open** → Home → `nis_IoT` → `raspberry` → нужный `.py`.
3. Запуск — зелёная кнопка **Run** или **F5**. Остановка — красная кнопка **Stop**.
   Крестик окна программы также завершает её и освобождает GPIO.
4. Ошибки появляются в нижней панели **Shell**. Если панели нет: **View → Shell**.

Перепрошивать уже работающую учебную microSD не требуется.
Перед подключением/перестановкой GPIO и шлейфа камеры выключать Raspberry
через меню **Shutdown**, затем отключать питание.

## 2. Выбрать Python-среду один раз

Если на учебной Raspberry уже настроена среда `env` и программы преподавателя
запускаются, использовать её. В Thonny нажать название интерпретатора **внизу справа** →
**Configure interpreter...** и выбрать Python этой среды, например:

`/home/ИМЯ_ПОЛЬЗОВАТЕЛЯ/env/bin/python3`

Если среды нет, открыть **Terminal** (значок терминала на панели) и выполнить:

```sh
python3 -m venv --system-site-packages ~/iot-env
source ~/iot-env/bin/activate
python -m pip install RPi.bme280 smbus2
```

Затем в Thonny выбрать Python из `/home/ИМЯ_ПОЛЬЗОВАТЕЛЯ/iot-env/bin/python3`.
Имя пользователя видно в начале строки терминала перед `@`; оно не обязательно `pi`.
Флаг `--system-site-packages` нужен для доступа к системным библиотекам камеры.

Если система сообщает, что нет venv, Tkinter или Pillow/ImageTk, установить
недостающие системные пакеты из терминала Raspberry:

```sh
sudo apt update
sudo apt install python3-venv python3-tk python3-pil.imagetk
```

Для проверки типа платы и ОС:

```sh
cat /proc/device-tree/model
cat /etc/os-release
```

### GPIO на разных Raspberry

На Pi 3/4 в старой учебной ОС обычно уже есть `RPi.GPIO`. На Pi 5 нужна совместимая
реализация `rpi-lgpio`, которая импортируется тем же именем `RPi.GPIO`.
На современной Raspberry Pi OS она устанавливается системным пакетом:

```sh
sudo apt install python3-rpi-lgpio
```

Не устанавливать одновременно `RPi.GPIO` и `rpi-lgpio` через pip в одну среду:
они занимают один и тот же модуль. Если в учебном `env` через pip уже установлен
старый RPi.GPIO, не смешивать его с новым; создать отдельный `iot-env` командой выше
после установки системного совместимого GPIO-пакета.
На старой Pi 3/4 с работающим RPi.GPIO заменять библиотеку ради замены не нужно.

## 3. Как считать контакты Raspberry

**Во всех наших программах используется BOARD: физические номера 1–40.**
Например, **физический контакт 12 — это GPIO18**, а не GPIO12.
Номера GPIO, напечатанные на расширителе, могут обозначать BCM, а не физический номер.

Найти контакт **1** по маркировке платы, схеме GPIO или подписанному расширителю.
Дальше контакты идут парами: **1–2, 3–4, 5–6...**; по одной стороне нечётные,
по другой — чётные. Не определять номер по словам «левый» и «правый» без ориентации платы.

Используемые контакты:

| Физический номер | Назначение |
|---:|---|
| 1 | 3.3V |
| 2 или 4 | 5V |
| 3 | SDA, GPIO2 |
| 5 | SCL, GPIO3 |
| 6 | GND |
| 7 | GPIO4 — кнопка R |
| 11 | GPIO17 — кнопка G |
| 12 | GPIO18 — сигнал серво |
| 13 | GPIO27 — кнопка B |
| 29 | GPIO5 — отдельный LED тревоги |
| 31 | GPIO6 — R RGB |
| 35 | GPIO19 — G RGB |
| 37 | GPIO26 — B RGB |

На **сигнальные GPIO** Raspberry подавать только 3,3 В. Контакты питания 5 В
в №2 предназначены для питания серво, а не для кнопок и входов датчиков.

## №1 — RGB и три кнопки

Файл: **lab01_rgb.py**.

### Собрать

- Общий катод/«−» RGB-модуля → **GND, физический 6**.
- R → через **220 Ом** к физическому **31**.
- G → через отдельные **220 Ом** к физическому **35**.
- B → через отдельные **220 Ом** к физическому **37**.
- Первая кнопка: при нажатии соединяет **3.3V, контакт 1**, с **контактом 7**.
- Вторая: 3.3V → кнопка → **11**.
- Третья: 3.3V → кнопка → **13**.
- От каждого кнопочного входа **7/11/13** поставить отдельные **10 кОм → GND**.

Пины RGB специально совпадают с №3, чтобы потом сохранить эту часть схемы.
Это небольшая адаптация разводки №1 из PDF; входы кнопок и требуемое поведение сохранены.
У четырёхногой кнопки использовать контакты, которые соединяются именно при нажатии.

### Открыть и нажать

1. В Thonny открыть **lab01_rgb.py** и нажать **F5**.
2. Появится окно **Lab 1 - RGB LED**.
3. Нажать первую аппаратную кнопку и отпустить:
   красный канал включится, окно покажет `RED: ON`.
4. Нажать её снова: красный выключится, появится `RED: OFF`.
5. Аналогично проверить остальные кнопки: `GREEN` и `BLUE`.
6. Включить два канала подряд — получится смешанный цвет; включить все три —
   смесь R+G+B. Оттенок белого зависит от модуля.

Окно показывает последний переключённый канал. Уже включённые каналы продолжают светиться,
поэтому итоговый цвет светодиода может отличаться от цвета надписи.
На Pi 5 с `rpi-lgpio` программный фильтр ждёт 25 мс устойчивого сигнала от кнопки.

Если цвета или кнопки перепутались, сначала собрать только красный канал и одну кнопку.
При `RED: ON` в окне и другом цвете на светодиоде проверить вывод R и его провод до контакта 31.
Если нажатие ничего не меняет в окне, проверить контакты кнопки, её провод до контакта 7 и шину 3.3V.
Для RGB с маркировкой R/G/B/GND следовать маркировке. У неподписанного четырёхвыводного RGB
расположение выводов зависит от модели. Для этой схемы нужен общий катод.

Завершить программу крестиком окна. Если закрывается не то окно — нажать Stop в Thonny.

## №2 — камера и сервопривод

Основной файл: **lab02_camera.py** — современная ОС с Picamera2.
Запасной: **lab02_camera_legacy.py** — только старая Pi 3/4 с уже работающим legacy-picamera.
Интерфейс в обоих вариантах одинаковый, Tkinter; PySimpleGUI не требуется.

### Собрать

- При полностью отключённом питании вставить подходящий шлейф камеры в разъём
  **CAMERA/CSI**. У Pi 3/4 не перепутать его с разъёмом DISPLAY.
  На Pi 5 используются разъёмы CAM/DISP и другой узкий шлейф/переходной кабель.
- Контакты шлейфа должны совпасть с контактами разъёма; защёлку закрыть ровно.
  Ориентацию синей стороны не переносить вслепую с другой модели платы.
- Красный провод серво → **5V, физический 2 или 4**.
- Коричневый/чёрный провод серво → **GND, физический 6**.
- Оранжевый/жёлтый сигнальный провод → **физический 12, GPIO18**.

Трёхцветный светодиод и кнопки №1 для этой работы не нужны. Физически крепить камеру
к серво методичка не требует: достаточно проверить фотографирование и поворот.
Если от движения серво Raspberry перезапускается, нужна проверка питания комплекта.

### Сначала проверить камеру

На современной ОС в Terminal:

```sh
rpicam-hello --list-cameras
```

Ожидается список камер с названием вроде `imx219` и номером `0`.
На раннем Bullseye современная команда может называться:

```sh
libcamera-hello --list-cameras
```

Проверить фотографию:

```sh
rpicam-still -o ~/nis_IoT/raspberry/test.jpg
```

Если доступен только `libcamera-still`, использовать его с теми же параметрами.
Закрыть окно проверки камеры перед запуском скрипта: одновременно камеру занимает
только одна программа.

Если `import picamera2` не работает на современной ОС:

```sh
sudo apt install python3-picamera2
```

Использовать установку apt и среду с `--system-site-packages`, а не случайные
несовпадающие версии Picamera2/libcamera из pip.

Для **уже настроенной старой legacy-системы** Pi 3/4 проверить:

```sh
raspistill -o ~/nis_IoT/raspberry/test.jpg
```

Если эта команда работает, а современного стека камеры нет, использовать
**lab02_camera_legacy.py**. На Pi 5 legacy-вариант не использовать.
Отсутствие Picamera2 само по себе ещё не означает, что камера работает через legacy.

### Открыть и нажать

1. В Thonny открыть **lab02_camera.py** и нажать **F5**.
   Для подтверждённого legacy-стека открыть вместо него `lab02_camera_legacy.py`.
2. Появится окно **Spying Eye** с кнопками **LEFT**, **TAKE PICTURE**, **RIGHT**.
3. Нажать **RIGHT** несколько раз: серво должен поворачиваться шагами по 10°.
   В Shell выводится `Angle: ...`. В начале угол команды равен 0°, LEFT из 0°
   не уменьшит его — поэтому начинать проверку с RIGHT.
4. Нажать **LEFT**: поворот в обратном направлении. Диапазон ограничен 0–160°.
5. Нажать **TAKE PICTURE**: в окне появится фотография с камеры.
6. Направить камеру в другую сторону и нажать **TAKE PICTURE** ещё раз:
   изображение должно обновиться.

Фото сохраняется как **image.png рядом со скриптом**, то есть в `~/nis_IoT/raspberry`.
В File Manager открыть эту папку и дважды щёлкнуть image.png, если нужно посмотреть
снимок отдельно. Путь сохранения также печатается в Shell.

Крестик окна завершает программу, останавливает PWM и освобождает камеру/GPIO.
Если возникает `Camera error`, текст будет в Shell; старое фото не означает,
что новый снимок успешно получен.

## №3 — датчик среды, RGB и LED тревоги

Файл: **lab03_weather.py**.

### Собрать

Нужен **BME280**. Похожий BMP280 не измеряет влажность; наш скрипт это проверяет.
Если выдали BMP280, нужен BME280 либо согласованная замена задания.

- Датчик VCC/VIN → **3.3V, физический 1**.
- GND датчика → **GND, физический 6**.
- SDA/SDI датчика → **физический 3**.
- SCL/SCK датчика → **физический 5**.
- RGB подключить как в №1: R/G/B через отдельные 220 Ом к **31/35/37**, общий → GND.
- Дополнительный красный LED: **физический 29 → анод LED → 220 Ом → GND**.

Если №3 идёт после №1, RGB и его резисторы можно оставить; кнопки отключить.
Маркировка реального датчика важнее порядка ножек на рисунке. Для модулей с CS/SDO
потребуется их разводка под I2C; нельзя оставлять выбор интерфейса/адреса неопределённым.

### Включить I2C

В Terminal:

```sh
sudo raspi-config
```

Выбрать **Interface Options → I2C → Yes → Finish**. Если система попросит перезагрузку,
перезагрузить Raspberry. Затем проверить адрес датчика:

```sh
i2cdetect -y 1
```

Ожидается **76** или **77**. Если команды нет, установить `sudo apt install i2c-tools`.
Если оба адреса пустые, сначала исправить питание/соединения/I2C.

### Открыть и нажать

1. Если адрес **76**, ничего в файле не менять.
2. Если адрес **77**, в Thonny найти строку с `default=0x76`, изменить на
   **default=0x77** и сохранить **Ctrl+S**.
3. Открыть **lab03_weather.py**, нажать **F5**.
4. Появится окно с **Temperature**, **Humidity**, **Pressure**, прогнозом и `Over 30 C`.
5. Смотреть: температура в °C, влажность в %, давление в **мм рт. ст.**,
   данные обновляются примерно раз в секунду. Эти же измерения идут в Shell.
6. Осторожно согреть датчик пальцами: температура должна постепенно измениться.
   При **30 °C и выше** загорается отдельный LED на контакте 29; ниже порога гаснет.
   Пальцами не всегда удаётся достичь порога — зависит от условий.

RGB зависит от измеренного давления:

- от **1022,69 гПа** — жёлтый, прогноз «Ясно / устойчиво»;
- от **1009,14** до 1022,69 гПа — зелёный, «Облачно»;
- ниже **1009,14 гПа** — синий, «Дождливо».

Мы выводим давление в мм рт. ст., но пороги в коде сравниваются с исходными гПа.
Цвет среднего диапазона выбран зелёным по тексту задания; в образце кода PDF
этот диапазон сделан белым. Погода не меняется по нажатию: при стабильном давлении
RGB будет одного цвета. Влажность и перевод единиц, которые требуется дописать,
в нашей программе уже реализованы.

## Границы готовности

Подготовлены все три проекта, включая два варианта камеры, и инструкция запуска.
На Windows проверены синтаксис и отдельные программные сценарии. Настоящие GPIO,
камера, серво, датчик и конкретная учебная ОС требуют проверки на месте.
